# Инструкция по настройке интеграции с AmoCRM

## 1. Настройка Webhooks в AmoCRM

Для того чтобы AmoCRM могла уведомлять наше приложение об изменениях (например, смене статуса сделки), необходимо настроить Webhooks:

1. Зайдите в ваш аккаунт AmoCRM.
2. Перейдите в раздел **Аналитика** -> **Настройки** (шестеренка вверху) -> **Webhooks** (или **Настройки** -> **Интеграции** -> **Webhooks** в зависимости от версии интерфейса).
3. Нажмите кнопку **Добавить хук**.
4. В поле **URL для отправки** введите адрес вашего сервера:
   `https://<ваш-домен>/api/v1/webhooks/amo_crm`
5. Выберите события, на которые вы хотите подписаться (рекомендуется):
   - Сделка добавлена
   - Статус сделки изменен
   - Контакт изменен
6. Нажмите **Сохранить**.

## 2. Отладка через Swagger

В Swagger UI выделен отдельный блок **AmoCRM Debug** для ручного запуска синхронизации. Теперь запросы возвращают подробную информацию об ошибках напрямую из API AmoCRM:

- `POST /api/v1/debug/amo_crm/sync_order/{id}` — принудительно отправить заказ в AmoCRM. Возвращает `lead_id` или текст ошибки.
- `POST /api/v1/debug/amo_crm/sync_user/{id}` — принудительно синхронизировать данные пользователя (включая страну, согласия и дату регистрации).
- `POST /api/v1/debug/amo_crm/exchange_token` — ручной обмен `code` на токены. В случае ошибки выводит `code` и `body` ответа CRM.

## 3. Особенности реализации

- **Таймер A1**: Повторный запрос звонка для верификации (`/api/v1/a1/request`) ограничен интервалом в 30 секунд. При слишком частом обращении возвращается статус `429 Too Many Requests`.
- **Последний вход**: При успешной авторизации по телефону автоматически обновляется поле `LAST_LOGIN` в карточке контакта AmoCRM.
- **Возвраты**: При оформлении возврата создается задача (Task) в AmoCRM для менеджера.
- **Статусы**: Вебхук эндпоинт `/api/v1/webhooks/amo_crm` готов к приему обновлений статусов сделок.

## 3. Проверка логов

Все входящие вебхуки и результаты синхронизации логируются с префиксом `[AmoCRM]`:

```bash
# Просмотр логов в реальном времени
tail -f log/production.log | grep AmoCRM
```

## 4. Переменные окружения

Убедитесь, что в `.env` настроены следующие параметры:
- `AMO_CRM_SUBDOMAIN` — поддомен вашей CRM (например, `mycompany`)
- `AMO_CRM_ACCESS_TOKEN` — долгоживущий токен или текущий access_token
- `AMO_CRM_CLIENT_ID` — ID интеграции
- `AMO_CRM_CLIENT_SECRET` — Секретный ключ интеграции
- `AMO_CRM_REDIRECT_URI` — URL перенаправления (должен совпадать с настройками в AmoCRM)
