# Решения для категорий без продуктов на проде

## Текущая ситуация

**Проверка на проде показала:**
- **Всего категорий без продуктов:** 537
- **Числовые ID:** 509 (94.8%)
- **UUID:** 0 (0%)
- **Другие форматы:** 28 (5.2%)
- **С URL:** 537 (100% - все категории имеют URL!)
- **Без URL:** 0

## Причины отсутствия продуктов

### 1. HTML парсинг не находит продукты (ВЕРОЯТНО)

**Причины:**
- Структура HTML страниц IKEA изменилась
- Продукты загружаются динамически через JavaScript
- Парсер не находит новые паттерны данных
- Продукты находятся в других форматах (новые JSON структуры)

**Решение:** ✅ **РЕАЛИЗОВАНО** - Улучшен `CategoryProductsFetcher`:
- Добавлены новые паттерны поиска продуктов
- Расширен список селекторов для HTML парсинга
- Добавлен поиск в `<script type="application/json">`
- Добавлен поиск в `window.__IKEA_PRODUCTS__` и подобных переменных
- Добавлен поиск продуктов через data-атрибуты
- Добавлен поиск продуктов через ссылки на страницы продуктов
- Улучшено логирование для отладки

### 2. API по ID не возвращает продукты

**Причины:**
- ID категории не валиден для API
- API требует другие параметры
- Категория действительно не имеет продуктов в системе IKEA
- API блокирует запросы

**Решение:** ✅ **РЕАЛИЗОВАНО** - Улучшен `CategoryProductsSearchService`:
- Добавлен метод `optimal_strategies_for_category` для определения оптимального порядка стратегий
- HTML парсинг имеет приоритет 1 (все категории имеют URL)
- Добавлена стратегия поиска через дочерние категории
- Улучшено логирование с метриками

### 3. Категории-контейнеры без прямых продуктов

**Причины:**
- Категории могут быть контейнерами для подкатегорий
- Продукты находятся в дочерних категориях

**Решение:** ✅ **РЕАЛИЗОВАНО** - Добавлена стратегия `:children_categories`:
- Поиск продуктов в дочерних категориях
- Рекурсивный поиск в подкатегориях
- Автоматическое использование для категорий с детьми

## Реализованные улучшения

### 1. CategoryProductsFetcher - улучшенный HTML парсинг

**Новые возможности:**
- Поиск в `<script type="application/json">`
- Поиск в `window.__IKEA_PRODUCTS__`, `__PRODUCTS__`, `__PRODUCT_LIST__`
- Поиск через data-атрибуты (`data-product`, `data-item`, `data-product-data`)
- Поиск продуктов через ссылки на страницы продуктов
- Расширенный список селекторов для HTML элементов
- Детальное логирование для отладки

**Примеры новых паттернов:**
```ruby
# Поиск в application/json скриптах
doc.css('script[type="application/json"]')

# Поиск в window переменных
script_text.match(/__IKEA_PRODUCTS__\s*=\s*({.+?});/m)

# Поиск через data-атрибуты
doc.css('[data-product], [data-item], [data-product-data]')

# Поиск через ссылки
doc.css('a[href*="/products/"], a[href*="/p/products/"]')
```

### 2. CategoryProductsSearchService - новая стратегия

**Добавлена стратегия `:children_categories`:**
- Поиск продуктов в дочерних категориях
- Рекурсивный поиск в подкатегориях
- Автоматическое использование для категорий с детьми

**Обновлен `optimal_strategies_for_category`:**
- Для категорий с числовыми ID: HTML парсинг → API по ID → Альтернативный endpoint → Дочерние категории → API по названию
- Для категорий с UUID: HTML парсинг → Дочерние категории → API по названию

### 3. Улучшенное логирование

**Добавлено:**
- Логирование размера HTML для анализа
- Логирование найденных продуктов в каждом паттерне
- Детальная информация об ошибках парсинга
- Метрики успешных стратегий

## Рекомендации по использованию

### Для категорий без продуктов:

```ruby
# Автоматически используется оптимизированный порядок стратегий
category = Category.find_by(ikea_id: '700403')
products = CategoryProductsSearchService.search(category, offset: 0, limit: 50)

# Или явно указать стратегии
strategies = CategoryProductsSearchService.optimal_strategies_for_category(category)
products = CategoryProductsSearchService.search(category, strategies: strategies)
```

### Порядок стратегий для категорий без продуктов:

1. **HTML парсинг** (приоритет 1) - все категории имеют URL
2. **API по ID** (приоритет 2) - для числовых ID
3. **Альтернативный endpoint** (приоритет 3) - для числовых ID
4. **Дочерние категории** (приоритет 4) - если есть дети
5. **API по названию** (приоритет 5) - fallback
