## Анализ причин

### Основная причина: HTML парсинг не находит продукты

**Обоснование:**
- Все 566 категорий имеют URL
- У всех категорий нет дочерних категорий
- Это означает, что проблема в HTML парсинге или в том, что категории действительно пустые

**Возможные причины:**
1. **Структура HTML изменилась** - IKEA могла изменить структуру страниц
2. **Продукты загружаются через JavaScript** - требуется headless browser
3. **Категории действительно пустые** - в системе IKEA нет продуктов для этих категорий
4. **Нужны другие паттерны поиска** - продукты находятся в других форматах

### Вторичная причина: API по ID не работает

**Обоснование:**
- 546 категорий имеют числовые ID
- API может не возвращать продукты для этих ID

## SQL запросы для мониторинга

### Проверка категорий без продуктов:
```sql
SELECT 
  c.ikea_id,
  c.name,
  c.url,
  c.updated_at,
  (SELECT COUNT(*) FROM categories WHERE parent_ids::text LIKE '%"' || c.ikea_id || '"%') as children_count
FROM categories c
LEFT JOIN products p ON p.category_id = c.ikea_id
WHERE p.id IS NULL 
  AND (c.is_deleted IS NULL OR c.is_deleted = false)
ORDER BY c.updated_at DESC, c.name;
```

### Проверка эффективности улучшений:
```sql
-- Категории, которые получили продукты после улучшений
SELECT 
  c.ikea_id,
  c.name,
  COUNT(p.id) as products_count,
  MAX(p.created_at) as first_product_created,
  MAX(p.updated_at) as last_product_updated
FROM categories c
INNER JOIN products p ON p.category_id = c.ikea_id
WHERE c.ikea_id IN (
  -- ID категорий, которые были без продуктов
  SELECT ikea_id FROM categories 
  WHERE ikea_id IN ('700403', '50374', '50382', '700535', '48988')
)
GROUP BY c.ikea_id, c.name
ORDER BY products_count DESC;
```
