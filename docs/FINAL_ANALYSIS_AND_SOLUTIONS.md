## Анализ возможностей получения продуктов

### ✅ Вариант 1: HTML парсинг (ПРИОРИТЕТ 1)
**Статус:** ✅ **ИДЕАЛЬНО** - все 555 категорий имеют URL  
**Метод:** `CategoryProductsFetcher.fetch(category.url)`  
**Преимущества:**
- Работает для 100% категорий без продуктов
- Не зависит от формата ID
- Прямой доступ к данным со страницы категории

**Недостатки:**
- Зависит от структуры HTML страницы
- Может не работать, если продукты загружаются через JS
- Медленнее API запросов

**Рекомендация:** Использовать как основной метод для всех категорий без продуктов

### ✅ Вариант 2: API по ID категории (ПРИОРИТЕТ 2)
**Статус:** ✅ **ХОРОШО** - 537 категорий имеют числовые ID  
**Метод:** `IkeaApiService.search_products_by_category(category_id)`  
**Преимущества:**
- Быстрый и надежный
- Официальный API IKEA
- Возвращает структурированные данные

**Недостатки:**
- Работает только для числовых ID
- Может не работать для некоторых валидных ID
- Не работает для UUID

**Рекомендация:** Использовать как дополнительный метод для категорий с числовыми ID

### ✅ Вариант 3: API по названию категории (ПРИОРИТЕТ 3)
**Статус:** ✅ **СРЕДНЕ** - все категории имеют название  
**Метод:** `CategoryProductsSearchService.search(category, strategies: [:api_by_category_name])`  
**Преимущества:**
- Работает для всех категорий
- Не зависит от формата ID

**Недостатки:**
- Может возвращать продукты из других категорий
- Требует фильтрации результатов
- Менее точный, чем поиск по ID

**Рекомендация:** Использовать как fallback метод

### ⏳ Вариант 4: Комбинированный поиск (РЕКОМЕНДУЕТСЯ)
**Статус:** ⏳ **НЕ РЕАЛИЗОВАНО** - нужно добавить  
**Метод:** Использовать `CategoryProductsSearchService` с несколькими стратегиями  
**Преимущества:**
- Максимальное покрытие
- Высокая вероятность найти продукты
- Автоматический fallback между методами

**Реализация:**
```ruby
# Уже реализовано в CategoryProductsSearchService
CategoryProductsSearchService.search(
  category,
  offset: 0,
  limit: 50,
  strategies: [
    :api_by_category_id,      # Для числовых ID
    :html_parsing,             # Для всех категорий с URL
    :api_by_category_name     # Fallback
  ]
)
```

## Технические детали

### SQL запрос для получения категорий без продуктов:
```sql
SELECT 
  c.ikea_id,
  c.name,
  c.url,
  CASE 
    WHEN c.ikea_id ~ '^[0-9]+$' THEN 'numeric'
    WHEN c.ikea_id ~ '^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$' THEN 'uuid'
    ELSE 'other'
  END as id_type
FROM categories c
LEFT JOIN products p ON p.category_id = c.ikea_id
WHERE p.id IS NULL 
  AND (c.is_deleted IS NULL OR c.is_deleted = false)
ORDER BY c.name;
```

### Использование существующего сервиса:
```ruby

  strategies: [:api_by_category_id, :html_parsing, :api_by_category_name]

# Для категории с UUID или другим форматом

  category,

  limit: 50,
  strategies: [:html_parsing, :api_by_category_name]

```
