## Возможные причины отсутствия продуктов

### 1. HTML парсинг не находит продукты на странице
**Причины:**
- Продукты загружаются динамически через JavaScript
- Структура HTML изменилась
- Страница требует авторизации или показывает капчу
- Продукты находятся в другом формате (JSON-LD, data attributes)

**Проверка:**
- Нужно проверить реальную структуру HTML страниц категорий
- Проверить наличие JSON-LD данных
- Проверить наличие data-атрибутов с продуктами

### 2. API по ID не возвращает продукты
**Причины:**
- ID категории не валиден для API
- API требует другие параметры
- Категория не имеет продуктов в системе IKEA
- API блокирует запросы (rate limiting, Cloudflare)

**Проверка:**
- Нужно проверить ответы API для конкретных категорий
- Проверить статус коды ответов
- Проверить наличие ошибок в логах

### 3. Категории действительно пустые
**Причины:**
- Категории-контейнеры без прямых продуктов
- Категории для будущих продуктов
- Устаревшие категории

**Проверка:**
- Проверить наличие дочерних категорий
- Проверить дату обновления категории
- Проверить статус категории (is_deleted)

## Анализ текущего парсинга

### CategoryProductsFetcher
**Текущая реализация:**
- Ищет JSON-LD данные (`@type":"Product"`)
- Ищет данные в `window.__INITIAL_STATE__`
- Ищет данные в `data-hydration-props`
- Парсит HTML структуру (`[data-product-id]`, `.pip-product-compact`)

**Возможные проблемы:**
1. IKEA может использовать другую структуру данных
2. Продукты могут загружаться через AJAX после загрузки страницы
3. Структура HTML может измениться

### IkeaApiService
**Текущая реализация:**
- Использует endpoint `https://sik.search.blue.cdtapps.com/pl/pl/search`
- Отправляет POST запрос с `type: 'CATEGORY'` и `input: category_id`
- Ожидает числовой ID категории

**Возможные проблемы:**
1. Некоторые ID могут не работать через этот endpoint
2. API может требовать дополнительные параметры
3. API может блокировать запросы

### Решение 3: Добавить поиск через дочерние категории (ПРИОРИТЕТ 3)

**Проблема:** Некоторые категории могут быть контейнерами без прямых продуктов

**Решение:**
1. Если категория не имеет продуктов, искать в дочерних категориях
2. Рекурсивно обходить дерево категорий
3. Собирать продукты из всех подкатегорий

**Реализация:**
```ruby
def find_products_in_children(category)
  products = []
  category.children.each do |child|
    products.concat(child.products.to_a)
    products.concat(find_products_in_children(child)) # Рекурсивно
  end
  products
end
```

## Технические детали

### SQL запрос для получения категорий без продуктов:
```sql
SELECT 
  c.ikea_id,
  c.name,
  c.url,
  CASE 
    WHEN c.ikea_id ~ '^[0-9]+$' THEN 'numeric'
    WHEN c.ikea_id ~ '^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$' THEN 'uuid'
    ELSE 'other'
  END as id_type,
  (SELECT COUNT(*) FROM categories WHERE parent_ids::text LIKE '%"' || c.ikea_id || '"%') as children_count
FROM categories c
LEFT JOIN products p ON p.category_id = c.ikea_id
WHERE p.id IS NULL 
  AND (c.is_deleted IS NULL OR c.is_deleted = false)
ORDER BY c.name;
```

### Проверка наличия дочерних категорий:
```sql
SELECT 
  c.ikea_id,
  c.name,
  COUNT(child.ikea_id) as children_count
FROM categories c
LEFT JOIN products p ON p.category_id = c.ikea_id
LEFT JOIN categories child ON child.parent_ids::text LIKE '%"' || c.ikea_id || '"%'
WHERE p.id IS NULL 
  AND (c.is_deleted IS NULL OR c.is_deleted = false)
GROUP BY c.ikea_id, c.name
HAVING COUNT(child.ikea_id) > 0
ORDER BY children_count DESC;
```
