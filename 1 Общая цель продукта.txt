1) Общая цель продукта
MindReport — платформа для анализа телефонных разговоров (менеджер/клиент) с помощью LLM. Ключевая ценность: 10‑шаговый психологический/поведенческий разбор диалога, структурированные отчёты, экспорт PDF, API‑интеграция.
2) Основные доменные сущности
Analysis: центральная запись анализа. Хранит транскрипт, статус, модель, факты из диалога, итоговый отчёт, вложенные файлы (audio/text/image/pdf), связана с пользователем или API‑клиентом.
AnalysisStep: один шаг пайплайна (1–10). Хранит статус, payload запроса, сырое/JSON‑ответы, rendered‑HTML, статистику токенов/времени.
PromptTemplate: версии промптов (core/step), с метаданными, локалью, планом, типом отчёта.
KnowledgeBaseDoc + PromptTemplateKbLink: база знаний и её привязка к шагам.
RenderTemplate: шаблоны Liquid для рендера HTML по шагам.
ApiClient: HMAC‑клиент для интеграций с квотами.
User: Devise‑пользователи, роли, планы, токены, дневные лимиты.
Session: пользовательские сессии (группировка анализов).
SiteSetting / PlanSetting / Service: настройки тарифов, лимитов и видимости функций.
Дополнительно: LlmCallLog, GandalfKnowledgeFile, Footer, Answer, TopicIngestLog (вспомогательные/другие модули).
3) Основные пользовательские сценарии
3.1 Веб‑пользователь: запуск анализа
1) Пользователь создаёт анализ (через UI).
2) Запись Analysis создаётся со статусом queued.
3) Запускается RunAnalysisJob (фон).
4) Генерация шагов 1–10 с рендерами и итоговой готовностью.
5) Пользователь смотрит результаты, скачивает текст или PDF.
3.2 API‑клиент: анализ через JSON или файл
1) POST /api/analyses/upload (HMAC‑авторизация).
2) Варианты входа:
JSON (текст + доп.поле).
multipart (аудио или текст).
3) Если аудио — асинхронная транскрибация (TranscribeAudioJob).
4) После транскрипции: EnqueueAnalysisJobsJob → ExtractFactsJob → RunAnalysisJob.
5) API выдаёт статус и отчёты: /status, /report, /report_html, /report_text, /pdf.
3.3 Отдельная транскрибация (без анализа)
POST /api/transcribe → распознавание речи → диалоговый текст, ссылка на скачивание.
4) Пайплайн анализа (10 шагов)
Оркестрация: RunAnalysisJob
Статус анализа → processing.
Ждёт заполнения имён (если факты ещё не извлечены).
Последовательно выполняет шаги 1..10 через StepRunner.
При ошибке шагов → статус failed.
При успехе всех шагов → ready.
Генерация фактов: ExtractFactsJob
Вызывает DialogFactsExtractorLlm для извлечения:
seller_name, client_name, seller_goal, seller_desired_result,
sale_happened, price_mentioned, prepayment_mentioned.
Обновляет Analysis.
При изменении имён перерендеривает готовые шаги.
Сбор контекста: ContextSliceBuilder
Из каждого шага берётся «сжатый срез» (whitelist полей).
Эти срезы и JSON из шагов 1–3 подмешиваются в дальнейшие шаги.
Формирование промпта: AnalysisMessagesBuilder
Склеивает:
core system prompt,
system/user prompt шага,
KB‑документы,
данные/имена/транскрипт.
Добавляет глобальные правила стиля.
Вызов LLM: StepRunner
Выбор провайдера по модели (OpenAI / DeepSeek).
Сбор сообщений + контекст + cache.
Ожидаемый формат (JSON/Text) по метаданным.
Отправка, логирование, обработка ошибок.
Ответ сохраняется в AnalysisStep:
response_text, response_json, request_payload, токены, длительность.
Рендер HTML: StepsRender::StepXRenderer
Для каждого шага рендерится HTML через Liquid‑шаблоны:
берётся RenderTemplate из БД,
если нет — используется дефолт.
Итог хранится в analysis_steps.rendered_text.
5) Транскрибация аудио
Асинхронно (для анализа)
TranscribeAudioJob:
OpenaiTranscribe с verbose_json,
форматирование сегментов в диалог с таймкодами,
сохранение транскрипта в Analysis,
затем постановка анализа в очередь.
Отдельный API‑режим
Api::TranscribeController:
аудио → Transcriptions::OpenaiTranscribe,
форматирование в диалог,
сохранение в кеш и выдача ссылки на скачивание.
6) Отчёты и экспорт
API отчёты
/report_html — HTML со всеми шагами (кеш на 1 час).
/report_text — текст каждого шага.
/pdf — PDF через WickedPdf (HTML‑рендер).
Веб‑PDF
AnalysisReportPdf (Prawn) для скачивания в веб‑интерфейсе.
Дополнительные генераторы
FinalReportBuilder — markdown отчёт по шагам.
ReportGenerator — отдельный pipeline с PromptAssembler и KB‑инлайнами.
7) Управление промптами и базой знаний
Промпты
PromptTemplate хранит system/user, версии, план, report_kind, locale.
fetch выбирает лучшую активную версию по приоритетам.
Импорт из файлов
PromptFilesImporter:
Загружает Core_Analysis_Prompt_v4.0.md и step_*.txt из config/promts.
Создаёт новые версии, поддерживает override/metadata.
Привязывает KB‑доки к шагам.
База знаний
KnowledgeBaseDoc хранит тексты.
Линкуется к PromptTemplate через PromptTemplateKbLink.
Подмешивается в system‑сообщения шагов.
8) LLM‑интеграция и провайдеры
OpenAI
OpenaiCompatFast:
Responses API (text/json),
строгая обработка ошибок, ретраи и сетевые фейлы,
аудио‑транскрибация через multipart.
Адаптеры
LlmAdapters::OpenaiAdapter — основной.
DeepseekAdapter — проксирует в OpenAI‑формат.
AnthropicAdapter — заглушка (не реализован).
9) Авторизация, роли, квоты
Пользовательская авторизация
Devise: регистрация, подтверждение, логин.
Роли: user, admin, docs_admin.
Планы: free, pro, test.
Токены и лимиты учитываются через User#consume_tokens!.
API‑авторизация
ApiHmacAuth:
HMAC по заголовкам: X-Api-Key, X-Api-Timestamp, X-Api-Sign.
Проверка подписи и таймскью.
В dev окружении — упрощённый режим.
Квоты
ApiClient#daily_limit и consume!.
Для пользователей с plan_test — дневной лимит через RequestQuota.
10) Админ‑панель (Trestle)
Админка покрывает:
Analyses (метрики, шаги, факты, токены).
AnalysisSteps (payload/JSON/рендеры).
PromptTemplates (редактирование, metadata, KB‑файлы).
KnowledgeBaseDocs (контент KB).
LlmCallLogs, Users, SiteSettings, Quotas (по конфигу).
11) Документация API (Rswag)
/api-docs доступен только docs_admin.
Отдельная форма логина для документации (Docs::AuthController).
12) Вспомогательные функции и UI
Dashboard: история анализов, быстрый запуск.
Pages: лендинг, about.
Сервис‑флаги: Service.visible_for? управляет видимостью функций.
Sessions: группировка диалогов/анализов.
13) Кэширование и оптимизации
Кэш сообщений шага (30 мин).
Кэш текста KB на шаг.
Кэш HTML‑отчёта (API).
Защита от слишком длинных промптов (усечение контента).
Починка JSON, возвращённого LLM.
14) Результат для пользователя
На выходе система выдаёт:
10 структурированных шагов анализа,
финальные HTML‑отчёты,
экспорт PDF/текст,
доступ через Web и API.
